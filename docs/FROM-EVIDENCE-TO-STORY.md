# Make depth part of the workflow

A useful career account explains what a person noticed, decided and carried through. Search hits and activity totals rarely supply that account by themselves. The agent needs to manage the follow-up work, retain what it learns, and check that the final prose preserves it.

## The complete flow

Reuse context → scope sources → first account → deepen → challenge → person review → one reusable document.

| Stage | What happens | What carries forward |
|---|---|---|
| Reuse and scope | Read existing context, corrections and research state. Establish missing boundaries once. | Selected sources, purpose and unanswered questions. |
| First account | Read originals and connect a problem, decisions, personal action, shared work and outcome. | A useful provisional draft with evidence and gaps. |
| Deepen | Pursue the questions most likely to change the story; check earlier origins, later outcomes and overlooked work. | Specific additions and corrections, not merely more text. |
| Challenge | Check actor, action, state and chronology; revisit omitted evidence and contrary accounts. | Supported claims and material limits in the prose. |
| Person review | Ask about missing meaning and misrepresentation. Recheck affected claims after corrections. | The person's feedback; pending feedback keeps draft status. |
| Reuse | Save Work, Career timeline and Interview prep in one HTML with a private archive. Derive a resume or role comparison when requested. | Stable accounts and sources; new evidence updates the same document. |

The agent owns the passes; the person should not have to say "go deeper" between them. For new context, plan for several passes within the session where possible. A narrow correction reopens only affected work. The first draft is a foundation, not a measured percentage of a complete career history.

Keep each batch to a small set of questions and relevant originals. Save evidence, corrections, what changed and the next useful action before the working context becomes crowded. A saved assistant summary is a navigation aid, not independent evidence. The [agent guide](../skills/career-context-sheet/references/deepening-and-story.md) defines the operational loop and recovery state; it is included in the standalone bundle.

Finish the current scope after challenge when no material correction or consequential accessible lead remains. Missing access leaves a qualified claim and a specific source request; missing personal meaning leaves a draft question. A real run limit leaves a saved checkpoint and resume step. None requires fabricating a result or repeatedly researching unchanged evidence. Resume with the prompt in [Getting started](GETTING-STARTED.md).

## What the existing experiments teach

| Observed result | Product consequence |
|---|---|
| The first autonomous run left a trial thread unexpanded and missed a later standalone summary. | Track pending context and search earlier and later windows, not only replies to launch records. |
| The deep-thread run completed all 14 discovered contexts but omitted testing, migration work and limitations it had read. | Keep a compact evidence record available while writing. More retrieval cannot repair every synthesis failure. |
| The ownership run read all 39 accessible records and selected 70 exact spans, yet dropped reviewer credit and presented a planned action as completed. | Check actor, action and state in every consequential sentence, then check material evidence has survived the summary. |

## A worked fictional account

The [multi-source fixture](../ai-search-mvp/fixtures/multisource.corpus.json) follows an equipment pilot called Kite, later Harbor. The first planning message supports an intention to build a form. The code record supports implementation. The later operations message supports a particular correction and reported repeat use. Those are different facts.

An evidence-based draft for Contributor 01:

> I built the intake form for a one-team equipment-handoff pilot and later fixed its return-date field. Contributor 02 proposed the pilot and owned the policy; Contributor 03 supplied a policy correction. Contributor 04 ran the daily review and reported using the form again after the handoff. Later feedback still described help with exceptions, and no time saving had been measured.

Support: `main:origin`, `main:planning`, `docs:brief`, `repo:change`, `ops:handoff`, `ops:later` and `email:later`. This is an authored draft from fictional records, not an original person quotation. The sources do not explain the person's design tradeoffs or what the experience meant to them. Those remain useful questions.

The May desk note is a lead needing an identity check before inclusion in this episode. Its repost is not corroboration. The unrelated Harbor catalog stays separate. A scheduled review does not prove attendance. The inaccessible attachment stays unknown; the excluded channel stays unread.

## Evaluate story quality separately from retrieval

Use the worked account as a transparent regression case, not a blind benchmark. Give a researcher only the agreed scope and available source tools; hold these review criteria aside until it finishes. Record the model, prompt, budget, calls and first result. Test changed behavior on a fresh case before claiming improvement.

| Check | Evidence of success |
|---|---|
| Personal judgment | A specific decision survives, or the account says that the sources do not establish one. |
| Shared credit and action state | Proposal, policy, implementation, correction and daily operation retain their actors and states. |
| Later outcome | Reported repeat use survives, with one-team scope and the unresolved exceptions. |
| No invented result | No measured time saving, general rollout, completed calendar event or unsupported personal motive. |
| Evidence retention | Important read evidence survives the narrative; omissions have reasons. |
| Questions and continuity | The next question resolves a real gap; existing answers and reads are reused. |
| Boundaries | No excluded-source reads, publication or private-source material in the public project. |

The [multi-source comparison](MULTISOURCE.md) measures record retrieval and calls. It does not grade the narrative above. Deterministic tests can validate references and state handling; fair attribution and a recognizable personal story still require source review and the person's feedback.

## What is available now

The public skill now instructs an agent to run this loop, keep private continuation state and use the person's feedback. The HTML renderer preserves the resulting accounts, sources, shared credit and uncertainty. The optional research experiments demonstrate narrower components and retain their failures.

The [integrated fictional demo](RESEARCH-TO-SHEET.md) now connects the evidence journal, continuation queue, checked draft and sheet plan to HTML generation. Opening the example performs no research. There is no live connector bundle or production autonomous story engine; semantic review and testing retained meaning remain necessary even when the mechanical build passes.
