# Research across selected sources

Start with the agreed work, dates, source locations and exclusions. The portable sheet is the output; it is not a source connector. Use available authorized connectors or selected local exports. Never imply that installing this skill connects an account.

## Choose coverage for the question

For explicitly systematic collection, use `journey.coverage` as a source-location × calendar-month ledger. For question-led research, a compact collection map with inspected scope, unanswered questions and the next useful reads is sufficient. Do not fabricate monthly receipts or scan every location without a reason. Reuse the selected dates, accounts/folders/channels, exclusions and retention scope. Email is optional, alongside chat, documents, calendars, code and public writing. Existing records and their dates do not prove a month was exhaustively checked.

For each source-month:

1. Record the query/filter and source timezone. Enumerate in bounded batches; count discovered records separately from originals actually read. Retain stable IDs and deduplicate copies and cross-posts.
2. Inspect originals and relevant thread context, replies, revisions and attachments. Email collection stays within the approved mailbox/folders and dates; omit irrelevant personal correspondence. Distinguish event time, message time and later capture time.
3. Save selected evidence and meaningful episodes in the same private archive. A coverage receipt may reference a source before it has been selected into an account. Do not load the full mailbox or archive into a single model prompt.
4. Save a compact receipt after each batch: `streamId`, `month`, `status`, `note`, `sourceRefs`, `cursor`, `found`, `read`. The note records filters, timezone, inspected scope, limitations and next action. Keep the cursor until pagination ends. Checkpoints are reusable; do not reread completed batches solely to inflate depth.
5. Use `checked` only after the selected scope is read, pagination is exhausted, and a receipt and source references exist. Use `empty` for an exhausted zero-record search with its exact scope recorded; `blocked` for access failures, `excluded` for an explicit exclusion, and `in_progress` for partial reads or a budget stop. A blocked month remains unfinished. No result is not evidence of no work in that month.

Continue across the pending queue within the current authorization and budget. Rotate source locations when that prevents one busy platform consuming the whole run. Stop when the requested scope has been checked or explicitly excluded, or a real access/budget limit is reached; retain remaining work and the next exact action. This is coverage of selected records, not certification of a complete life story.

The onboarding UI can create the checklist, record receipts and copy a bounded collection task. It does not connect accounts or call a model. The coach performs authorized reads, updates the packet and saves an archive revision. Browser edits must first be included in a saved HTML so a later update does not overwrite them. Keep exact platform receipts private; the reusable skill carries only this method.

## Read beyond the first matching message

1. Inventory each selected location and its actual read capabilities. Record whether it can enumerate records, search only, read replies, follow pagination, or retrieve attachments. An accessible service does not imply access to every channel or folder.
2. Search the project's supplied names, earlier names and distinctive terms across the selected locations. Keep a small query ledger. A person or project sharing a name is a lead, not an identity match.
3. Open original records, their parent context and complete available replies. Paginate until the source reports its end; record truncation, access failures and unread attachments.
4. Follow explicit links into other selected locations. Record an out-of-scope reference without following it. Ask about expanding scope only if that gap materially changes the account.
5. Look separately for standalone earlier origins and later outcomes within the agreed date range. Later use, corrections or ownership changes may appear in a different channel without replying to the original thread.
6. Reconcile authors, project identity, copied messages and revisions. Preserve the original and repost relationship. Repetition is not independent corroboration; matching names alone never merge accounts.
7. Synthesize the account only after reading the selected context. Check personal contribution, other contributors, decisions, delivery, use, later changes and uncertainty separately. Retrieve more when a consequential claim lacks support or contradicting evidence remains unresolved.

For each location, retain what was read, the dates actually covered, open pagination, blocked reads and the next useful read. A complete search is not a complete archive. A complete inventory does not prove a complete or fair interpretation.

For saved agent conversations, separate user accounts, retrieved source text, assistant interpretation and intended actions. A chat summary may point to an original or capture a useful correction; it does not independently corroborate the source it summarized. Use the [deepening and story guide](deepening-and-story.md) to carry evidence into an account and resume unfinished work.

For repositories, posts and portfolios, [GitHub and social discovery](github-and-social.md) covers account enumeration, implementation/history checks, attribution and cross-posted evidence.

## Spend reads where they can change the story

Read the original account and linked evidence first. Then prioritize unresolved ownership, contradictory outcomes, later corrections, missing parent context and relevant attachments. Alternate locations so one busy channel does not consume the whole budget. On a budget stop, preserve a resumable queue and the limits in the sheet.

Calendar entries establish scheduled activity, not attendance or outcomes. Code establishes implementation activity, not adoption. A person's account can support a clearly attributed self-report without independent corroboration. Keep those distinctions in both prose and agent text.
